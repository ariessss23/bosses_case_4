## 2\. Формула severity (заполни)

deviation\_pct = (value - norm\_max) / norm\_max × 100 # при превышении
или (norm\_min - value) / norm\_min × 100 # при недоборе

Если 0 < deviation\_pct ≤ 5: severity = низкий → WARNING
Если 5 < deviation\_pct ≤ 10: severity = высокий → WARNING
Если deviation\_pct > 10: severity = критический → CRITICAL
Если value = "" или нет данных: severity = нет сигнала → STALE
Если norm\_min ≤ value ≤ norm\_max: severity = норма → NORMAL

**Обоснование порогов:** 5% — это уровень естественного шума датчика. 10% — это уже реальная угроза (например, 2.6 градуса для птицы), при которой нужна немедленная эскалация.

## 6\. Дедупликация (заполни)

**Правило:** если в течение 5 минут пришло 2 события с одинаковыми
`location + indicator` — считать одно.

Как реализовать:
if (location, indicator) in seen and (now - seen\[(location, indicator)]) < 5 min:
→ игнорировать (DUPLICATE)
else:
→ обработать, обновить seen\[(location, indicator)] = now



**Вопрос:** почему это важно? Ответ: защита от спама датчиков. Если датчик сломался и шлет 100 ошибок, диспетчер перестанет их читать и пропустит реальную аварию.
