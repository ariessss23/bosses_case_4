# ER-модель — кейс 4 «Ситуационный центр»

## Как заполнять

Дана одна сущность (Site) как образец и связи. Заполни остальные 5 сущностей,
их атрибуты и связи. Для каждой сущности укажи PK/FK, типы и обязательность.

## 1\. Сущности (6)

|Сущность|Что хранит|Зачем|
|-|-|-|
|Site|участок: id, имя, зона|привязка датчиков и инцидентов|
|Sensor|датчик: id, участок, тип, статус|источник телеметрии|
|Measurement|показание: id, датчик, время, значение, нормы, статус|факт телеметрии для расчета|
|Incident|инцидент: id, тип, участок, время, ответственный, статус, срок|реестр проблем|
|Alert|оповещение: id, показание, важность, действие, время|результат срабатывания правил|
|AuditEvent|журнал: id, тип объекта, id объекта, действие, кто, время|безопасность и разбор споров|

**Подсказки:**

* Sensor — датчик, привязан к участку.
* Measurement — показание от датчика (value, time, status).
* Incident — реестр проблем (type, location, status, responsible).
* Alert — результат срабатывания правила (severity, action).
* AuditEvent — журнал для ИБ и разбора споров.

## 3\. Связи (заполни)

|Связь|Тип|Обоснование|
|-|-|-|
|Site → Sensor|1:N|на участке несколько датчиков|
|Site → Incident|1:N|на участке может быть много инцидентов|
|Sensor → Measurement|1:N|один датчик дает много показаний|
|Measurement → Alert|1:N|по одному показанию может быть несколько алертов|
|Incident → AuditEvent|1:N|каждый переход статуса — событие аудита|
|Alert → AuditEvent|1:N|каждое срабатывание правила — событие аудита|

**Подсказки:**

* 1:N — на участке несколько датчиков / инцидентов.
* 1:N — один датчик даёт много показаний.
* 1:N — по одному показанию может быть несколько алертов.
* 1:N — каждый переход статуса / алерт — событие аудита.
